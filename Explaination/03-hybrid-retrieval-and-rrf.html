Module 03: Hybrid Retrieval & Reciprocal Rank Fusion (RRF)

Concurrent Semantic & Keyword Search with Rank-Based Fusion

1. Why Hybrid Retrieval? (The Dual-Failure Problem)

In enterprise travel operations, neither dense semantic search nor sparse keyword search is sufficient on its own:

  • Dense Search Failure (Semantic Gap): Dense embeddings excel at conceptual meaning ("hotel reimbursement policy" matches "lodging expense rules"). However, they struggle with exact identifiers, codes, numbers, and proper nouns ("$250", "Yellow Fever", "BK-000001", "PIR report"). Dense embeddings often project distinct numbers close together in embedding space.
  • Sparse Search Failure (Vocabulary Mismatch): BM25 keyword matching excels at exact lexical matching. However, if a user asks "Can I get my money back if I cancel?", BM25 will completely miss documents mentioning "100% refund voucher" due to vocabulary mismatch.
The Hybrid Solution: Execute both dense (Qdrant with BAAI/bge-m3) and sparse (BM25Okapi) concurrently, and fuse the results using rank positions rather than incomparable raw similarity scores.

3. Reciprocal Rank Fusion (RRF) Algorithm

Because Dense scores (cosine 0 to 1) and BM25 scores (unbounded term-frequency logs) are on completely different mathematical scales, linear score addition (alpha * dense + (1-alpha) * bm25) fails unless extensive per-dataset normalization is performed.

RRF Solves This: It uses rank positions (1st place, 2nd place, etc.) instead of raw scores. 

# RRF Mathematical Formula:
RRF_Score(document d) = SUM [ 1 / (k + rank_r(d)) ]  for all retrievers r

Where:
- rank_r(d) is the 1-based rank position of document d in retriever r.
- k is a smoothing constant (default: 60, per Cormack et al. 2009).
- If a document appears in multiple retrievers, its RRF score compounds.

4. Asynchronous Parallel Concurrency

Running dense and sparse retrieval sequentially adds their latencies together (e.g. 50ms + 30ms = 80ms). HybridRetriever.asearch() executes both simultaneously using asyncio.gather:

5. Implementation Deep-Dive (src/retrieval/hybrid_retriever.py)

def reciprocal_rank_fusion(
    results_list: list[list[Document]],
    k: int = 60,
) -> list[Document]:
    """
    RRF algorithm: score(d) = sum(1 / (k + rank_i(d))).
    Deduplicates documents by unique chunk identifier.
    """
    scores: dict[str, float] = defaultdict(float)
    doc_map: dict[str, Document] = {}

    for results in results_list:
        for rank, doc in enumerate(results, start=1):
            key = (
                getattr(doc, "id", None)
                or doc.metadata.get("chunk_id")
                or doc.metadata.get("source", "") + str(hash(doc.page_content))
            )
            scores[key] += 1.0 / (k + rank)
            if key not in doc_map:
                doc_map[key] = doc

    sorted_keys = sorted(scores.keys(), key=lambda x: scores[x], reverse=True)
    return [doc_map[key] for key in sorted_keys]

class HybridRetriever:
    async def asearch(self, query: str | dict) -> list[Document]:
        """Run all retrievers concurrently via asyncio.gather, fuse results via RRF."""
        tasks = [self._invoke_retriever_async(r, query) for r in self.retrievers]
        all_results = await asyncio.gather(*tasks)
        fused = reciprocal_rank_fusion(list(all_results), k=self.rrf_k)
        return fused[: self.final_k]

6. Key Architectural Trade-Offs

Weighted Score Sum Requires min-max normalization; breaks when BM25 score spikes on long documents. RRF is completely immune to score scaling and calibration drift.
Dense-Only Retrieval Misses 25%+ of exact policy numbers and airline codes. Benchmark proved BM25 achieves 0.800 Hit@1 on travel terms vs 0.743 Dense.
Sequential Retrieval Higher tail latency (sum of dense + sparse response times). asyncio.gather executes both in parallel, bound only by the slower service.

7. Senior Engineering Interview Defense

Q1: Why does BM25 sometimes outperform dense vector retrieval on corporate policy documents?

Answer: Corporate travel guidelines are characterized by exact thresholds and statutory codes: "$250 domestic hotel cap", "14 days advance booking", "Yellow Fever certificate". Dense embedding models map text into semantic latent space, where numbers and acronyms often cluster together. BM25 computes exact lexical term frequency (TF) and inverse document frequency (IDF), guaranteeing that rare exact matches receive maximum ranking weight.

Q2: Why is the smoothing constant k set to 60 in Reciprocal Rank Fusion?

Answer: The constant k=60 was empirically established in the original Cormack, Clarke, and Buettcher (SIGIR 2009) paper. It acts as a dampener to prevent a single top-1 result from completely dominating over a document that ranks highly (e.g. rank 2 or 3) across multiple independent retrievers. Setting k too low gives undue weight to noisy rank 1 outliers; setting k too high flattens score differences.
