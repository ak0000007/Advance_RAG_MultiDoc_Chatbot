Module 05: Self-Correcting RAG: Relevance Grading & Query Rewriting

Autonomous Feedback Loops, Pydantic Document Grading & Fail-Safe Diagnostic Fallbacks

1. The Need for Self-Correction (Why Naive RAG Fails)

In traditional Naive RAG, retrieval is a one-shot blind pipeline: 

User Query → Vector Search → Top-K Chunks → LLM Generation → Answer

If the user's query is vaguely phrased (e.g., "What happens if I don't show up?"), the vector search may retrieve general travel tips rather than the penalty clause for flight no-shows. In naive RAG, the LLM hallucinates an answer or provides generic advice because it has no mechanism to question whether its retrieved context is actually relevant.

Self-Correcting RAG (CRAG): Introduces an active reflection loop where an evaluator LLM grades retrieved chunks against the question. If irrelevant, an LLM query rewriter diagnoses why the retrieval failed and reformulates the search query.

3. Pydantic Structured Output Grading

Unstructured LLM evaluations ("Yes", "It seems relevant") are prone to parsing failures. We enforce schema validation using Pydantic: 

class RetrievalGrade(BaseModel):
    """Binary score and rationale for relevance check on retrieved documents."""
    relevant: bool = Field(
        ...,
        description="True if documents contain information answering the question, False otherwise."
    )
    reason: str = Field(
        ...,
        description="Detailed explanation justifying the relevance decision."
    )

The prompt uses PydanticOutputParser with strict formatting instructions, guaranteeing deterministic boolean outputs.

4. Contextual Query Rewriting

When the grader determines that retrieved chunks are irrelevant, passing the same query back to the retriever would produce the exact same failure.

The build_corrective_rewriter takes two inputs:

  1. question: The user's original inquiry.
  2. reason: The grader's explanation of why previous chunks failed (e.g., "Retrieved chunks discussed cancellation deadlines, but omitted monetary refund percentages").

The rewriter strips conversational filler, expands synonyms, and targets specific semantic keywords.

5. The Grader Fail-Safe Architecture

The Silent Failure Anti-Pattern

Previously, if the relevance grader crashed (due to LLM network timeout or rate limits), it caught the exception and silently assumed relevance: 

# FLAWED PATTERN (Silent Swallowing):
except Exception as e:
    logger.warning(f"Grading failed: {e}")
    relevant = True  # Pretends evaluation succeeded, concealing errors!

The Production Fail-Safe Solution

Silent failure is dangerous in enterprise auditing. When grading fails, the system logs the full stack trace with logger.error(..., exc_info=True) and explicitly tags the context payload with a loud diagnostic banner: 

# PRODUCTION FAIL-SAFE:
except Exception as e:
    logger.error(
        f"CRITICAL: Retrieval grading failed on attempt {attempt}: {e}. "
        f"Returning retrieval context with unverified flag to prevent silent failure.",
        exc_info=True,
    )
    return f"[UNVERIFIED RETRIEVAL - Grader Evaluation Failed: {e}]\n\n{context}"

6. Code Implementation Deep-Dive (src/tools/document_search.py)

def build_document_search_tool(retriever, grader_llm, rewriter_chain, max_attempts: int):
    @tool
    async def search_documents(query: str, config: RunnableConfig) -> str:
        current_query = query
        conf = config.get("configurable", {}) if isinstance(config, dict) else {}
        tenant_id = conf.get("tenant_id")
        active_filter = {"tenant_id": str(tenant_id)} if tenant_id else None

        for attempt in range(1, max_attempts + 1):
            documents = await retriever.ainvoke({
                "question": current_query,
                "metadata_filter": active_filter,
            })
            if not documents:
                return "No relevant documents were found for this query."

            context = "\n\n".join([format_document_citation(doc, i)[0] for i, doc in enumerate(documents, 1)])

            # Structured Grading with Fail-Safe Fallback
            try:
                parser = PydanticOutputParser(pydantic_object=RetrievalGrade)
                grade = await grader_llm.ainvoke({
                    "question": query,
                    "context": context,
                    "format_instructions": parser.get_format_instructions(),
                })
                relevant = grade.relevant
                reason = grade.reason
            except Exception as e:
                logger.error(f"CRITICAL: Grading failed: {e}", exc_info=True)
                return f"[UNVERIFIED RETRIEVAL - Grader Evaluation Failed: {e}]\n\n{context}"

            if relevant:
                return context

            # Self-Correction: Rewriting Query for next attempt
            if attempt < max_attempts:
                current_query = await rewriter_chain.ainvoke({
                    "question": query,
                    "reason": reason,
                })

        return "Note: Relevance could not be fully confirmed.\n\n" + context

    return search_documents

7. Senior Engineering Interview Defense

Q1: Why should an agentic RAG system rewrite queries instead of asking the user for clarification?

Answer: Frequent clarification questions create high user friction and poor UX. Most retrieval failures stem from vocabulary mismatch or anaphora ("Can I change it?"). By incorporating the conversation history and the grader's diagnostic rationale, the rewriter can autonomously resolve ambiguities (e.g. rewriting to "Can employee change departure date on booking BK-000001?"). If re-retrieval still fails after the maximum attempts (2), the system then gracefully falls back or clarifies.

Q2: Why is structured output via Pydantic preferable over free-form JSON parsing in LLM grading?

Answer: LLMs frequently return leading conversational filler (e.g., "Here is the JSON evaluation: ...") or unescaped quotes that break standard json.loads(). PydanticOutputParser injects formal schema instructions and schema validation. If the output fails validation, the error is caught deterministically rather than propagating an uncaught JSONDecodeError.
