Module 02: Ingestion, Chunking & Deduplication Engine

Multi-Format Parsing, Semantic Text Splitting & Idempotent Upserting to Vector & Keyword Stores

1. Ingestion Overview & Problem Space

The foundation of any enterprise RAG system is its document ingestion pipeline. In commercial travel operations, documents arrive in multiple formats: PDF contracts, Word policy amendments, CSV airline price grids, Excel booking sheets, and plain text FAQs.

Common Ingestion Failures:

  • Random ID Duplication: Generating random UUIDs on re-indexing duplicates all vector embeddings, causing index bloat and degraded retrieval accuracy.
  • Vector/Keyword Store Drift: Populating Qdrant while failing to update BM25 destroys hybrid search parity.
  • Context Fragmentation: Naive character splitting chops crucial policy sentences in half (e.g., splitting "$250 cap" across chunks).

3. Semantic Chunking Strategy

We employ DocumentChunker (in src/chunking/splitter.py), configuring RecursiveCharacterTextSplitter with:

  • Chunk Size: 1,000 characters (~200–250 tokens), aligning with paragraph boundaries.
  • Chunk Overlap: 200 characters (~40–50 tokens), preventing semantic cutoff at boundaries.
  • Separators Priority: ["\n\n", "\n", " ", ""]. Keeps full paragraphs together first, sentences second, and individual words third.

4. Deterministic Hashing & RFC 4122 UUIDv5

To ensure idempotent ingestion, every chunk's unique identifier is deterministically computed from its invariant properties. Re-running ingest.py ten times will produce identical IDs, enabling upsert without duplicate vector growth.

flowchart LR Tenant["tenant_id\n('acme_corp')"] --> Formatter Source["source path\n('policy.txt')"] --> Formatter ChunkIdx["chunk index\n(0, 1, 2...)"] --> Formatter Content["chunk content\n('Cancellations...')"] --> SHA256["SHA-256 Hash"] SHA256 --> Formatter["Formatted Seed:\n{tenant_id}:{source}:{idx}:{hash}"] Formatter --> UUIDv5["uuid.uuid5(NAMESPACE_URL, seed)"] UUIDv5 --> CID["Deterministic RFC 4122 UUIDv5"]

5. Ingestion & Dual Store Synchronization

Both dense (Qdrant) and sparse (BM25) stores must be updated in unison. ingest.py synchronizes both stores:

flowchart TD RawDocs["Raw Document Directory (data/)"] --> Loader["MultiDocumentLoader"] Loader --> Chunker["DocumentChunker (1000/200)"] Chunker --> Dedup["ID Generator (UUIDv5) + Tenant Stamping"] Dedup --> Split{"Parallel Upsert"} Split --> Qdrant[("Qdrant Vector Store\n(add_documents with doc_ids)")] Split --> BM25[("BM25 Inverted Index\n(add_documents + save to pickle)")]

6. Code Implementation Deep-Dive (ingest.py)

def generate_chunk_id(doc, chunk_idx: int, tenant_id: str = "default") -> str:
    """Generate deterministic RFC 4122 UUIDv5 based on tenant, source, index, and content hash."""
    source = doc.metadata.get("source", "unknown")
    content_hash = hashlib.sha256(doc.page_content.encode("utf-8")).hexdigest()
    return str(uuid.uuid5(uuid.NAMESPACE_URL, f"{tenant_id}:{source}:{chunk_idx}:{content_hash}"))

def main():
    parser = argparse.ArgumentParser(description="Ingest documents with deterministic IDs and tenant isolation.")
    parser.add_argument("--data-dir", default="./data", help="Directory with documents to index")
    parser.add_argument("--tenant-id", default="default", help="Tenant ID for document isolation")
    args = parser.parse_args()

    loader = MultiDocumentLoader(data_directory=args.data_dir)
    docs = loader.load_directory()
    
    chunker = DocumentChunker(chunk_size=1000, chunk_overlap=200)
    chunks = chunker.split_documents(docs)

    doc_ids = []
    for idx, chunk in enumerate(chunks):
        chunk.metadata["tenant_id"] = args.tenant_id
        cid = generate_chunk_id(chunk, idx, tenant_id=args.tenant_id)
        chunk.id = cid
        chunk.metadata["chunk_id"] = cid
        doc_ids.append(cid)
    
    # Store in Qdrant with deterministic IDs (idempotent upsert)
    qdrant.vector_store.add_documents(chunks, ids=doc_ids)

    # Persist in BM25Store
    bm25_store = BM25Store.load(bm25_path) if bm25_path.exists() else BM25Store()
    bm25_store.add_documents(chunks)
    bm25_store.save(bm25_path)

8. Senior Engineering Interview Defense

Q1: What happens if an operator runs the ingestion script twice on the same folder?

Answer: Because we use deterministic UUIDv5 hashing based on tenant:source:chunk_index:content_hash, re-running ingestion generates the exact same document IDs. Qdrant performs an idempotent point upsert, overwriting existing vectors with identical embeddings. In BM25Store, add_documents checks existing_keys and prunes duplicate chunk IDs before updating the inverted index.

Q2: Why is chunk overlap necessary, and what are the trade-offs of setting it too high?

Answer: Overlap guarantees that sentences crossing chunk boundaries are not truncated, maintaining semantic coherence. However, setting overlap too high (e.g. >40%) bloats the vector index size, increases embedding generation costs, and increases the risk of returning redundant chunks during retrieval.
