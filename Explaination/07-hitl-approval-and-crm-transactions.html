Module 07: Human-in-the-Loop (HITL) Approval & Transactional CRM Execution

Two-Phase Commit Patterns, LangGraph interrupt() State Suspension & Safe CRM Mutations

1. The Need for HITL in AI Operations

Granting an LLM direct, autonomous write permissions to corporate CRM databases is an existential operational risk. An LLM can:

  • Hallucinate record IDs and overwrite unrelated customer bookings.
  • Misinterpret ambiguous statements ("Cancel my trip") and delete expensive corporate contracts.
  • Fall victim to prompt injection embedded in document attachments.
The Non-Negotiable Rule: The LLM may propose mutations, but only a verified human operator can execute them.

3. LangGraph interrupt() Lifecycle

LangGraph provides first-class interrupt() primitives:

  1. Pause: When interrupt(payload) is invoked, execution in that node halts immediately.
  2. Checkpoint: The entire graph state (including messages, pending tool calls, and variables) is flushed to the checkpointer (PostgreSQL).
  3. Return: The stream yields, and FastAPI inspects snapshot.next, detecting that the graph is waiting at the human_approval node.
  4. Resume: Calling graph.astream(Command(resume=decision), config) injects the decision directly into the suspended variable and continues execution from the exact line where it paused.

4. Identity & State Retention on Resume (Fixing Debt C3)

A common pitfall in async interrupt architectures is identity loss. When the user resumes via POST /chat/resume, the frontend only sends thread_id and decision; it rarely re-sends the user's Salesforce username or tenant identifier.

In src/api/routes.py, we inspect the PostgreSQL checkpoint before resuming to restore identity: 

# Restore authenticated context from checkpoint state:
snapshot = await graph.aget_state(base_config)
thread_sf_username = snapshot.values.get("sf_username") or auth_user
thread_tenant_id = snapshot.values.get("tenant_id") or "default"

config = _build_config(
    request.thread_id,
    thread_sf_username,
    trace_id=trace_id,
    endpoint="resume",
    tenant_id=thread_tenant_id,
)

5. Code Implementation Deep-Dive (src/graph/approval.py)

def build_human_approval_node(salesforce_client=None, pool=None):
    async def human_approval_node(state: RAGState, config: RunnableConfig) -> dict:
        messages = state.get("messages", [])
        last_tool_msg = messages[-1]
        proposal = json.loads(last_tool_msg.content)

        approval_request = {
            "action": proposal.get("action"),
            "record_id": proposal.get("record_id"),
            "changes": proposal.get("changes"),
            "proposed_by": state.get("sf_username", "unknown"),
        }

        # Suspend execution and await human input via /chat/resume
        decision = interrupt(approval_request)

        if str(decision).strip().lower() not in ("approve", "approved", "yes", "true"):
            return {
                "messages": [AIMessage(content="Operation cancelled by user.")],
                "answer": "Operation cancelled by user.",
            }

        # Human approved: Execute actual CRM PATCH operation
        client = salesforce_client or get_salesforce_client()
        result = await client.update_record(
            sobject=proposal.get("sobject"),
            record_id=proposal.get("record_id"),
            fields=proposal.get("changes"),
            sf_username=state.get("sf_username"),
        )

        current_writes = state.get("write_count", 0)
        return {
            "write_count": current_writes + 1,
            "messages": [AIMessage(content=f"Successfully executed update: {result}")],
        }

    return human_approval_node

6. Senior Engineering Interview Defense

Q1: How does your architecture ensure that a human approval request cannot be bypassed by prompt injection?

Answer: The approval gate is enforced in compiled Python graph routing, not by the LLM. Mutating tools are hardcoded to never issue Salesforce PATCH calls; they merely return a JSON dictionary marked with "__requires_approval__": True. The graph's conditional edge inspector (_after_tool_router) unconditionally routes this dictionary to the human_approval node, which executes an unavoidable LangGraph interrupt(). Even if a prompt injection attempts to instruct the LLM to skip approval, the LLM physically lacks any tool capable of mutating the CRM without going through the interrupt gate.

Q2: What happens if the server crashes while an approval request is pending user review?

Answer: Because state persistence is backed by PostgreSQL checkpoints (AsyncPostgresSaver), the entire memory snapshot, message history, and suspended node pointer are durably written to the database before the interrupt() response is returned to the client. The application server can crash, restart, or scale horizontally across different pods. When the user eventually approves the change hours or days later, any available pod reads the thread checkpoint from PostgreSQL and seamlessly resumes execution.
