Module 01: System Overview, Architecture & Multi-Tenant Foundations

Enterprise Travel Operations AI Copilot with LangGraph, Hybrid Retrieval & Multi-Tenant CRM

1. Executive Overview & Problem Space

Advance_RAG_Chatbot is an enterprise-grade autonomous AI copilot designed for corporate travel operations. Unlike generic Q&A chatbots, it executes complex transactional workflows combining:

  • Document-Grounded RAG: Answers policy, flight, hotel, and insurance inquiries using hybrid semantic + keyword retrieval without hallucinating.
  • Transactional Salesforce CRM Operations: Inspects and modifies live enterprise records (Bookings, Travel Packages, Payments, Opportunities) via custom Apex REST endpoints.
  • Deterministic Human-in-the-Loop (HITL): Reversible state interrupts pause mutating operations until an authorized human operator approves the payload.
  • Multi-Tenant Data Partitioning: Strictly isolates vector chunks, inverted indices, and session state across corporate client accounts.
Key Engineering Focus: Productionizing AI requires moving past simple chains to state machines, strict authorization boundaries, constant-time cryptography, and deterministic safety guards.

4. Multi-Tenant Isolation Design

In a multi-tenant corporate copilot, Tenant A (e.g., Acme Corp) must never see or retrieve documents from Tenant B (e.g., Beta Global). A security breach in RAG occurs if a shared vector database returns nearest neighbors across tenant boundaries.

Three-Pillar Isolation Strategy

  1. Ingestion Namespace Stamping: At indexing time (ingest.py --tenant-id <id>), every document chunk is assigned a deterministic RFC 4122 UUIDv5 derived from {tenant_id}:{source}:{chunk_idx}:{content_hash}, and stamped with chunk.metadata["tenant_id"] = tenant_id.
  2. Identity Scoping via Config: The incoming API token resolves to an AuthUser containing tenant_id. FastAPI injects this into RunnableConfig["configurable"]["tenant_id"].
  3. Mandatory Retrieval Filtering: search_documents extracts tenant_id from the config and applies metadata_filter={"tenant_id": tenant_id}. In both Qdrant payload queries and BM25 inverted index lookups, chunks with non-matching tenant IDs are disqualified before scoring.

5. Constant-Time Auth & Timing Attack Protection

Standard string equality (token == secret_key) is vulnerable to timing attacks. Python compares strings byte-by-byte and terminates execution upon encountering the first mismatched character. By measuring sub-millisecond network latency variations, an attacker can determine the secret key one byte at a time. 

# VULNERABLE:
if token != required_key:  # Early exit leaks key length and byte positions
    raise HTTPException(401)

# SECURE (Constant-Time):
import secrets
if not secrets.compare_digest(token, required_key):  # Always scans all bytes in fixed time
    raise HTTPException(401)

6. Production Code Deep-Dive

Authenticated User Resolution & Configuration (src/api/routes.py)

class AuthUser(str):
    """
    Authenticated user wrapper carrying username and tenant_id context.
    Inherits from str so existing string consumers continue to function seamlessly.
    """
    username: str
    tenant_id: str

    def __new__(cls, username: str, tenant_id: str = "default"):
        obj = super().__new__(cls, username)
        obj.username = username
        obj.tenant_id = tenant_id
        return obj

def _verify_auth_and_get_user(
    auth_bearer: Optional[HTTPAuthorizationCredentials] = Security(security_bearer),
    api_key: Optional[str] = Security(security_api_key),
) -> Optional[AuthUser]:
    token = None
    if isinstance(auth_bearer, HTTPAuthorizationCredentials):
        token = auth_bearer.credentials
    elif isinstance(api_key, str):
        token = api_key

    # 1. Check api_key_mapping first (maps specific tokens to {username, tenant_id})
    if settings.api_key_mapping and token:
        for mapped_key, user_info in settings.api_key_mapping.items():
            if secrets.compare_digest(token, mapped_key):
                if isinstance(user_info, dict):
                    uname = user_info.get("username") or settings.sf_default_username or "api_user"
                    tid = user_info.get("tenant_id") or "default"
                else:
                    uname = str(user_info)
                    tid = "default"
                return AuthUser(uname, tid)

    # 2. Check global api_secret_key with constant-time comparison
    required_key = settings.api_secret_key.get_secret_value() if settings.api_secret_key else None
    if required_key:
        if not token or not secrets.compare_digest(token, required_key):
            raise HTTPException(status_code=401, detail="Invalid authentication credentials.")
        if settings.sf_default_username:
            return AuthUser(settings.sf_default_username, "default")
        return None

    # 3. Dev mode fallback
    if settings.sf_default_username:
        return AuthUser(settings.sf_default_username, "default")
    return None

Think of the RunnableConfig as a diplomatic pouch carried with every message through the agent's brain. 9. Senior Engineering Interview Defense

Q1: How do you prevent cross-tenant data leaks when multiple customers share a single vector database?

Answer: We apply strict pre-filtering at the database level rather than post-filtering in memory. At ingestion time, every chunk is stamped with tenant_id. During retrieval, the authenticated user's tenant_id is retrieved from server-side JWT/API key mappings and injected directly into the Qdrant filter DSL and BM25 store inverted index query. Chunks from other tenants are excluded before cosine or BM25 scoring occurs.

Q2: Why use LangGraph over traditional ReAct loops or autonomous agent loops like AutoGPT?

Answer: Enterprise operations require determinism and durability. LangGraph models workflows as explicit cyclic state graphs with checkpointing. If an update requires human approval, LangGraph fires interrupt() and serializes the complete conversation graph to PostgreSQL. The server can restart, and days later a human can resume the exact state via /chat/resume.

Q3: How does the system defend against timing attacks on authentication endpoints?

Answer: Standard string comparison aborts at the first non-matching byte, creating subtle differences in response time that attackers use to deduce secrets character-by-character. We enforce secrets.compare_digest(), which executes in constant time regardless of where or whether characters match.
