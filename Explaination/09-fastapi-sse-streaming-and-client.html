1. Enterprise FastAPI Architecture

The API gateway (src/api/app.py and src/api/routes.py) provides the interface connecting client web applications, external chatbots, and corporate webhooks to the LangGraph core.

  • Lifespan Management: Database pools (psycopg_pool.AsyncConnectionPool) and vector clients are initialized during startup and cleanly drained on shutdown, avoiding connection leaks.
  • CORS Hardening: Configurable origin parsing protects internal enterprise endpoints from cross-site scripting vulnerabilities.
  • Dependency Injection (DIP): dependencies.py builds the heavy graph, retriever, and LLM instances once as cached singletons, keeping routes focused strictly on HTTP protocol translation.

2. Server-Sent Events (SSE) Streaming Protocol

Waiting 4–6 seconds for a multi-step agent to finish retrieval, grading, and final generation produces unacceptable perceived latency. POST /chat/stream streams execution events in real time using Server-Sent Events (SSE).

3. Persistent HTTP Connection Pooling (SalesforceAsyncClient)

The TLS Handshake Bottleneck

Creating a new httpx.AsyncClient() for every outbound CRM request wastes 80–120ms per call re-negotiating TCP handshakes and TLS certificates with Salesforce servers.

Connection Pooling & Rate-Limit Backoff

SalesforceAsyncClient maintains a persistent httpx.AsyncClient singleton equipped with:

  • Connection Limits: httpx.Limits(max_keepalive_connections=20, max_connections=50).
  • Automatic Session Recovery: If the client is accidentally closed or encounters network partition, it self-heals by instantiating a fresh session.
  • Exponential Backoff on 429: Retries rate-limited Apex calls using jittered exponential backoff (2^attempt + jitter).

4. Dynamic Citation Extraction (src/retrieval/citations.py)

Retrieved documents format citations into XML attributes: <document source="policy.txt" title="Travel Policy" chunk_id="uuid">.

Before responses leave the API, regex extractors parse these attributes, producing structured Pydantic Citation objects: 

class Citation(BaseModel):
    source: str
    title: str
    chunk_id: Optional[str] = None
    page: Optional[int] = None

The frontend UI renders these as interactive chips at the bottom of the response, linking users directly to the authoritative corporate source files.

5. Code Implementation Deep-Dive (src/api/routes.py)

async def _stream_graph_events(graph, inputs, config: dict, thread_id: str):
    """Multiplex LangGraph events into Server-Sent Events (SSE)."""
    async for event in graph.astream_events(inputs, config, version="v2"):
        kind = event["event"]

        # Stream status on tool invocations
        if kind == "on_tool_start":
            tool_name = event.get("name", "tool")
            yield f"event: status\ndata: {json.dumps({'step': f'Running {tool_name}'})}\n\n"

        # Stream LLM tokens in real time
        elif kind == "on_chat_model_stream":
            chunk = event.get("data", {}).get("chunk")
            if chunk and hasattr(chunk, "content") and chunk.content:
                yield f"event: token\ndata: {json.dumps({'delta': chunk.content})}\n\n"

    # Check for approval interrupt or completion
    snapshot = await graph.aget_state(config)
    if snapshot.next:
        # Paused at approval interrupt
        interrupt_val = snapshot.tasks[0].interrupts[0].value
        yield f"event: interrupt\ndata: {json.dumps({'approval_request': interrupt_val})}\n\n"
    else:
        # Completed normally
        answer = snapshot.values.get("answer", "")
        citations = snapshot.values.get("citations", [])
        yield f"event: done\ndata: {json.dumps({'answer': answer, 'citations': citations})}\n\n"

6. Senior Engineering Interview Defense

Q1: Why choose Server-Sent Events (SSE) over WebSockets for conversational AI streaming?

Answer: SSE operates over standard HTTP/1.1 or HTTP/2, requiring no custom handshake, protocol upgrading, or stateful proxy configurations. It is lightweight, unidirectional (server-to-client), and natively supports browser auto-reconnect via EventSource. WebSockets add unnecessary full-duplex protocol complexity for request-response chat patterns where client-to-server traffic is infrequent compared to server-to-client token streams.

Q2: How do you handle HTTP 429 Too Many Requests errors when integrating third-party enterprise APIs like Salesforce?

Answer: We implement an exponential backoff strategy with full jitter. If Salesforce returns a 429 response, the client inspects the Retry-After header if present; otherwise, it delays the retry by min(max_backoff, base * 2^attempt) + random_jitter. Adding random jitter prevents the "thundering herd" problem where multiple concurrent workers retry at the exact same millisecond.
